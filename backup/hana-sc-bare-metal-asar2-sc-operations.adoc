Este capítulo resume las operaciones de copia de seguridad, restauración y recuperación, actualización del sistema SAP y replicación asíncrona con SnapCenter.



[[backup-operations]]
== Operaciones de backup

Las operaciones de copia de seguridad se llevan a cabo tal y como se describe en https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html["Obtenga información sobre las operaciones de respaldo para SAP HANA Snapshot en SnapCenter"].


NOTE: Si no se ha configurado ningún grupo de consistencia para la unidad de almacenamiento, SnapCenter crea un grupo de consistencia y un grupo de consistencia secundario con la primera operación de copia de seguridad de Snapshot. Luego, el almacenamiento de datos de HANA se asigna al grupo de consistencia secundario. Las copias de seguridad de Snapshot de SnapCenter aparecen dentro del grupo de consistencia secundario.

image:hana-sc-bare-metal-asar2-image-007.png["width=601,height=191"]

image:hana-sc-bare-metal-asar2-image-008.png["width=601,height=205"]



[[restore-and-recovery]]
== Restauración y recuperación

Las operaciones de restauración y recuperación se llevan a cabo tal y como se describe https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html["Restaurar y recuperar bases de datos de SAP HANA con SnapCenter"].



[[asynchronous-storage-replication]]
== Replicación asíncrona del almacenamiento

Para el volumen de datos de HANA, se ha configurado una replicación asíncrona del almacenamiento.

image:hana-sc-bare-metal-asar2-image-009.png["ancho=601, alto=180"]

La replicación se ha configurado con la política MirrorAndVault.

image:hana-sc-bare-metal-asar2-image-010.png["ancho=601,alto=206"]

La política MirrorAndVault incluye diferentes etiquetas y retenciones de SnapMirror.

image:hana-sc-bare-metal-asar2-image-011.png["width=601,height=235"]

En SnapCenter se ha configurado una política para que coincida con la etiqueta "daily" de SnapMirror de la política MirrorAndVault de ONTAP.

image:hana-sc-bare-metal-asar2-image-012.png["ancho=378,alto=354"]

Al usar la política MirrorAndVault de ONTAP, SnapCenter muestra copias separadas de Vault y Mirror, aunque las copias de seguridad de instantáneas solo están disponibles una vez en el almacenamiento de destino.

image:hana-sc-bare-metal-asar2-image-013.png["ancho=601, alto=294"]



[[sap-system-refresh]]
== Actualización del sistema SAP

Para obtener información más detallada sobre las operaciones de actualización y clonación del sistema SAP mediante SnapCenter, consulta https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-introduction.html["Automatización de las operaciones de copia y clonado del sistema SAP HANA con SnapCenter"].



[[snapcenter-workflow]]
=== SnapCenter flujo de trabajo

Los detalles de la operación y los requisitos previos se describen en https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations["Actualización del sistema SAP HANA con SnapCenter"]. En concreto, el sistema de destino debe añadirse a SnapCenter antes de poder ejecutar la primera operación de actualización o clonación.

En el primer paso del proceso de clonación, debes proporcionar el host de destino y el SID de destino.

image:hana-sc-bare-metal-asar2-image-014.png["ancho=333,alto=313"]

La selección de protocolo debe ser "FCP".

image:hana-sc-bare-metal-asar2-image-015.png["ancho=334,alto=312"]

Opcionalmente, puedes añadir el script sc-system-refresh.sh para automatizar la operación de recuperación.

image:hana-sc-bare-metal-asar2-image-016.png["ancho=352,alto=331"]

La siguiente captura de pantalla muestra el registro de tareas del flujo de trabajo de clonación.
